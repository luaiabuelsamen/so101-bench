# Thread C — Runtime Safety Enforcement for Learned Policies

Reading notes, 2026-08-16. Thread agent for the so101-bench publication push.

**Thesis under test:** on low-cost robots, the binding constraint on learned manipulation is observability — not data scale, not model scale — and the missing observations are already latent in the actuators and logs the fleet ships with.

**Our result being positioned:** a ~30-line runtime guard for BC grasping policies on simulated SO-101 (stall-detected contact from jaw position-register history + bounded squeeze cap) removed 96% of crush events (85/180 -> 3/180) across three checkpoints, paired episodes, no retraining, no dynamics model, no privileged state — bus telemetry only. Caveats we measured: it deletes successes earned by over-gripping; stall detector precision 0.78 against jams; detection must compare measured motion against servo-feasible (not commanded) travel.

Every entry below carries the URL(s) actually fetched. Partial reads are flagged. Verdict line judges the paper against the thesis and our result.

---

## 1. Alshiekh, Bloem, Ehlers, Könighofer, Niekum, Topcu — "Safe Reinforcement Learning via Shielding" (AAAI 2018)

Fetched: https://ar5iv.labs.arxiv.org/html/1708.08611 (full text)

The founding "shield" paper: a reactive system, synthesized by solving a safety game over a finite-state abstraction of the environment dynamics plus an LTL safety spec, either pre-filters the action set (preemptive) or overrides selected actions (post-posed) — "the shield monitors the actions of the agent, and substitutes the selected actions by safe actions whenever this is necessary" (§5.2). It proves a minimal-interference property ("restricts the agent as rarely as possible and forbids actions only if they could endanger safe system behavior", §6) and finds shielded agents often learn *faster*, not slower. Requirements are non-negotiable: an MDP abstraction of the dynamics and effectively full state — "the method fundamentally depends on knowing which actions are unsafe, requiring some environment model"; sensing, partial observability, and real robots never appear (experiments are gridworlds, a 2D car, Atari, a water tank). This is the canonical statement that safety should be a separate correct-by-construction layer rather than a learned property of the policy.

**Verdict: For the enforcement-layer position (Q3), Orthogonal to the observability thesis.** The shield consumes abstract state that someone else must supply; for contact events on a $100 arm, that abstraction is exactly the thing nobody has — our guard replaces the safety game with a register-history heuristic and gives up the guarantee.

## 2. Ames, Coogan, Egerstedt, Notomista, Sreenath, Tabuada — "Control Barrier Functions: Theory and Applications" (ECC 2019 tutorial)

Fetched: https://ar5iv.labs.arxiv.org/html/1903.11199 (full text)

The reference formulation of the minimally-invasive safety filter: solve a QP minimizing ||u − k(x)||² subject to the barrier condition L_f h + L_g h u ≥ −α(h(x)), so the nominal controller is modified "in a minimal way so as to guarantee safety" (§II-C). The machinery assumes control-affine dynamics ẋ = f(x) + g(x)u with locally Lipschitz f, g, full state x for the Lie derivatives, and a hand-supplied barrier function h. Nothing on model-free operation, measurement error, or learned nominal controllers; applications are cruise control, bipeds (DURUS), Segway, and swarms — no manipulation, no grasping, no low-cost hardware. Crush events on an SO-101 are not even expressible in this language without a contact-state observation to put inside h.

**Verdict: Orthogonal, leaning Against as precedent.** The dominant formal filter line presupposes precisely the model + state observability the thesis says low-cost robots lack; it is the thing our guard is *not*, and the useful inheritance is only the minimal-modification objective, which our squeeze cap crudely mimics.

## 3. Hobbs, Mote, Abate, Coogan, Feron — "Run Time Assurance for Safety-Critical Systems: An Introduction to Safety Filtering Approaches for Complex Control Systems" (IEEE Control Systems Magazine 2023)

Fetched: https://arxiv.org/pdf/2110.03506 (downloaded, read pp. 1–10 of the arXiv v2 PDF); Simplex lineage cross-checked via a reading-group deck on Sha's 2001 IEEE Software paper: https://engineering.purdue.edu/dcsl/reading/2007/foob-using_simplicity_to_control_complexity.pdf (secondary source — slides, not the paper)

The modern tutorial for the Simplex/RTA position: "RTA Systems are online verification mechanisms that filter an unverified primary controller output... a *monitor* that watches the state of the system and output of a primary controller, and a *backup controller* that replaces or modifies control input when necessary" (p. 2), opening with the F-16 Auto GCAS save. It contains the cleanest published version of the argument our guard rides on: "the assurance mechanism is constructed in a way that is entirely agnostic to the underlying structure of the primary controller"; "safety verification does not become more difficult as the primary controller grows more complex, and the verification process does not need to be repeated when changes are made to the primary controller" (pp. 2–3) — which is exactly why one guard worked unchanged across three BC checkpoints. It names RTA "an attractive solution to bounding the behavior of machine learning and AI systems" because verifying the neural controller itself is usually precluded (pp. 3–4), and lists manipulator arms among application domains. But the formalism is set invariance over state constraints φ(x) ≥ 0 with dynamics ẋ = F(x,u): the monitor watches *state*, and the possibility that the needed signal is missing and must be recovered from actuator telemetry is never contemplated. The Sha slides confirm the 2001 core claim: the key is "the existence of a simple and reliable core component that ensures system's critical functions" — one "can exploit features and performance of complex software even it cannot be verified, provided it is possible to guarantee the critical requirements with simple software."

**Verdict: For on the enforce-don't-learn question, Orthogonal on observability.** Our guard is a degenerate Simplex (monitor = stall detector, backup = squeeze cap) whose novelty relative to this canon is only *what the monitor watches*: a servo register history instead of a modeled state.

## 4. Brunke, Greeff, Hall, Yuan, Zhou, Panerati, Schoellig — "Safe Learning in Robotics: From Learning-Based Control to Safe Reinforcement Learning" (Annual Review of Control, Robotics, and Autonomous Systems 2022)

Fetched: https://ar5iv.labs.arxiv.org/html/2108.06266 (full text)

The field's taxonomy: safety Level I (soft/encouraged), Level II (probabilistic), Level III (hard constraints satisfied at all times), crossed with three approach families — learning uncertain dynamics, safe/robust RL, and certification of learned controllers (§2.1.3, §3). Throughout, "we assume direct access to (possibly noisy) measurements of the robot state" (§2.1.1); certification methods additionally need a nominal or learned dynamics model and online constrained optimization, and the survey explicitly scopes out perception. No approach in the survey operates from actuator telemetry alone, and contact-rich manipulation safety is absent. The conservatism–performance trade is a running theme ("robust control and robust MPC are conservative... this usually yields poor performance", §2.2), with the safety problem reduced to "knowing what is not known."

**Verdict: For, by documented omission.** The definitive map of safe robot learning shows every certification family consuming state + model and none addressing grasp-force hazards on cheap hardware — in its vocabulary our guard is a Level III hard constraint on a *proxy* variable (register travel), enforced with no model, which sits outside its axes. That gap is the thesis.

## 5. Hsu, Hu, Fisac — "The Safety Filter: A Unified View of Safety-Critical Control in Autonomous Systems" (Annual Review of Control, Robotics, and Autonomous Systems 2024)

Fetched: https://arxiv.org/abs/2309.05837 and https://ar5iv.labs.arxiv.org/html/2309.05837 (full text)

Unifies all safety filters into two functions — "every safety filter can be conceptualized as two complementary functions: *monitoring* and *intervention*" (§6) — with a safety monitor, fallback policy, and intervention scheme, and tabulates the families: HJ reachability (model + full state + grid computation, "exponential in the state dimension... no more than six continuous state variables", §6.1), CBFs (model, synthesis open), MPC filters (model + terminal set + online optimization), and learned filters, which "tend to lack well-understood guarantees, which can result in unpredictable catastrophic failures" (abstract). It proves a least-restrictive "perfect" filter exists (Prop. 1) but stresses real filters trade "permissiveness, robustness, generality, and computational scalability" and can induce boundary chatter, motivating filter-aware task policies (§7.4.3). Manipulation, contact, and proprioceptive-only sensing are absent; open problem 3 is verbatim our territory: "Modern robot autonomy increasingly rely on high-dimensional sensory input and learned latent representations. Reconciling these with rigorous safety guarantees grounded in dynamical models is an open and important research challenge" (§9).

**Verdict: For, structurally.** Our guard cleanly instantiates their decomposition (monitor = stall detector with 0.78 precision, intervention = squeeze cap) at a layer their table doesn't contain — no family runs from actuator measurements without a dynamics model — and their permissiveness axis is the right frame for our deleted over-grip successes.

## 6. Wabersich, Zeilinger — "A predictive safety filter for learning-based control of constrained nonlinear dynamical systems" (Automatica 2021)

Fetched: https://ar5iv.labs.arxiv.org/html/1812.05506 (full text)

The MPC-flavored filter: "the PSF receives the proposed control input and decides, based on the current system state, if it can be safely applied to the real system, or if it has to be modified otherwise," using a receding-horizon feasibility check with a data-driven probabilistic model, state- and input-dependent uncertainty bounds, and a terminal safe set with known local controller. Interference is minimal by construction (u₀ = u_RL whenever a safe backup trajectory exists), which is the cleanest statement of "filter only when you must." It cannot run without a model: safety is exactly the feasibility of a model-predicted backup trajectory. Experiments are simulated pendulum swing-up and quadrotor landing; no manipulation, no hardware.

**Verdict: Against the idea that certified minimal intervention comes cheap; Orthogonal to manipulation.** The certified version of what we built costs a learned dynamics model, uncertainty quantification, and online optimization — on a Feetech bus none of these exist, which is why our filter checks a register history instead of a backup trajectory and holds no guarantee.

## 7. Li, Li, Tseng, Girard, Filev, Kolmanovsky — "Safe Reinforcement Learning Using Robust Action Governor" (L4DC 2021)

Fetched: https://ar5iv.labs.arxiv.org/html/2102.10643 (full text)

The action-governor line (descended from reference/command governors): a supervision module "monitors the control signal generated by the RL agent and corrects the ones that may cause unsafe behavior," solving argmin ‖u − u_RL‖² over a safe action set derived from robust invariant sets of a discrete-time linear model with bounded disturbance, via online MIQP; unlike reference governors it "modifies controller output signal, i.e. ... can be placed closer to the environment/plant." Validation is simulated adaptive cruise control; the governor eliminates training and deployment violations and even speeds learning, at ~30 ms/step solver cost. The set-theoretic machinery "fundamentally requires" the model — without it the unrecoverable-set recursion cannot be computed.

**Verdict: Orthogonal, with one useful inheritance.** RAG shares our placement (last box before the plant, wrapping an arbitrary learned policy, minimal deviation) but derives the safe set from a model rather than sensing contact; the governor tradition of reasoning about what commands the plant can feasibly track is the ancestral form of our servo-feasible-vs-commanded-travel caveat.

## 8. Haddadin, De Luca, Albu-Schäffer — "Robot Collisions: A Survey on Detection, Isolation, and Identification" (IEEE T-RO 2017)

Fetched: http://www.diag.uniroma1.it/~labrob/pub/papers/TRO_Collision_Dec2017.pdf (author-hosted PDF, read pp. 1292–1299: pipeline, monitoring methods, observers)

The definitive treatment of extracting contact events from a robot's own actuation signals: a seven-phase "collision event pipeline" (precollision, detection, isolation, identification, classification, reaction, postcollision), covering methods that "use only proprioceptive sensors" and are deployed in KUKA iiwa, Franka Emika, and ABB YuMi. Detection options range from the crude — "monitor the measured currents in robot electrical drives, looking for fast transients possibly caused by a collision" — to the reference method, the generalized momentum observer, which is a first-order filtered estimate of external joint torque but requires the identified rigid-body model (M̂, Ĉ, ĝ) plus measured currents with known torque gains or joint torque sensors. The survey is candid about our exact failure mode: "A major practical problem is the selection of a threshold on the monitoring signals, so as to avoid false positives and achieve high sensitivity at the same time," and the classification phase (accidental vs. intentional contact) is left largely open, with reaction limited to stop/retract/reflex/compliance. Strikingly for us, footnote 1 concedes "the same problem is relevant also in robot manipulation, where impacts may occur with an uncertain environment and potentially fragile objects" — and then the survey never returns to grippers or objects.

**Verdict: For the thesis — and the most dangerous prior work for our result.** Fifteen years of industrial practice proves contact observations are latent in actuator signals; what this line does *not* do is run without an identified dynamics model and calibrated torque constants, protect the *grasped object* rather than the human, or wrap a learned policy with measured competence cost — the three things our guard is about.

## 9. Dalla Libera, Tosello, Pillonetto, Ghidoni, Carli — "Proprioceptive Robot Collision Detection through Gaussian Process Regression" (ACC 2019)

Fetched: https://ar5iv.labs.arxiv.org/html/1905.08689 (full text); https://arxiv.org/abs/1905.08689 (metadata)

The nearest published thing to a positive answer to our Q1: learn a GP model of expected motor currents from collision-free operation and monitor the residual s = i − î, with "minimal sensing requirements, since it needs only to measure the joint coordinates and the motor currents" — no analytic rigid-body model, no torque sensors, unlike momentum-observer methods. Tested on a UR10 at 125 Hz, it detects collisions in dynamic and quasi-static motion, but it is detection only: "we do not discuss any strategy to design the threshold," no reaction, no policy in the loop, and the intended-vs-unintended contact problem is named and skipped ("discriminating between intended and unintended contacts"). It also still requires training a regression model per robot from clean data — the safety monitor is itself learned.

**Verdict: For.** Motor-telemetry-only contact detection exists in the literature — but as an unfinished front end: nobody closes the loop into enforcement, nobody wraps a learned policy, and the false-positive/precision problem we measured at 0.78 is exactly the part they defer.

## 10. Huang, Zambelli, Kay, Martins, Tassa, Pilarski, Hadsell — "Learning Gentle Object Manipulation with Curiosity-Driven Deep Reinforcement Learning" (arXiv 2019)

Fetched: https://ar5iv.labs.arxiv.org/html/1903.08542 (full text)

The learn-safety-into-the-policy alternative: penalize impact m_t = max(0, f_{t+1} − f_t) sensed by fingertip tactile sensors (BioTac on the real Shadow hand), and rescue learning with a curiosity bonus, because penalty-only training "gets stuck in a local optimum of avoiding all contact with the environment." Two sentences matter enormously for us. First, they dismiss actuator-level caps: "A naïve approach is to constrain the maximum torques that a robot's motors can exert. However, many manipulation tasks require occasional, momentary, or variable high force" — the published theoretical form of our measured caveat that the squeeze cap deletes successes a policy earned by over-gripping. Second, their contact-avoidance collapse is the training-time mirror of the same competence-vs-safety trade. The price of their route: tactile sensing, reward access, and full retraining (500k iterations in sim) per policy — none of which exist for BC checkpoints on a fleet arm.

**Verdict: Against the thesis as a strategy (safety via sensors + retraining), For our framing as a foil.** Where they need BioTacs and RL to make gentleness a policy property, we show a fixed cap recovers most of the benefit with zero retraining — and they correctly predict the cost we then actually measured.

## 11. Yin, Lu, Jiang, Mo — "Verifiable Model-Free Safety Filters via Reinforcement Learning" (arXiv 2026)

Fetched: https://arxiv.org/html/2605.05989v1 (full text); https://arxiv.org/abs/2605.05989 (metadata)

A test of what "model-free" means in the safety-filter literature: the filter is an unrolled QP-solver network whose parameters are trained by PPO in simulation, taking the current state x₀ and the reference input û and outputting a safe input, with intervention that adapts to noise level rather than being uniformly conservative. It escapes the *analytic* dynamics model but still requires ground-truth state observation, a training simulator, polytopic constraint specifications — and, tellingly, the certificate re-imports the model: verification of the trained filter is a QCQP/SOS program that "requires system model A, B... though model isn't needed for learning." Evaluation is simulation-only on double integrator, quadruple tank, and cartpole.

**Verdict: Orthogonal, and clarifying.** Even the branch of this literature explicitly branded model-free means "no analytic plant model," never "no state, no training, raw actuator registers"; no one in the filter canon means by model-free what our 30 lines actually are.

## 12. Römer, Balletshofer, Thumm, Pavone, Schoellig, Althoff — "From Demonstrations to Safe Deployment: Path-Consistent Safety Filtering for Diffusion Policies" (ICRA 2026)

Fetched: https://arxiv.org/html/2511.06385 (full text); https://arxiv.org/abs/2511.06385 (metadata)

The state of the art for safety filtering of imitation-learned manipulation: instead of perturbing actions (which drives the policy out of distribution), modulate speed *along the policy's own intended path* — "guarantee safety by modifying the joint speed q̇(t) and acceleration q̈(t) while staying on the intended trajectory" — with a concatenated failsafe stop, certified by set-based reachability (SaRA) at 1 kHz against ISO/TS 15066 constraints: speed-and-separation monitoring and power/force limiting as kinetic-energy caps (down to 0.014 J for hand contact). Requirements: trajectory optimization over robot kinematics/dynamics, reachable-set computation, and externally measured human/object state with bounded error; on a real Franka FR3 across sorting/handover/feeding, task success is ~80% with the filter vs ~79% without, while "safe success" goes 0% -> 80% — and the CBF baseline collapses task success to 4% vs their 69–72% in sim. Contact force is handled as pre-impact energy bounding of the *arm*; grasp force on the object in the jaws is outside the constraint set.

**Verdict: Against the necessity of our minimalism on rich hardware, For our trade analysis.** This is what manipulation safety filtering costs when done properly (models + reachability + exteroception on a torque-controlled arm); its two key findings — naive filtering destroys competence via distribution shift, path-consistency preserves it — are the sophisticated version of the trade our cap exposes, and its silence on gripper crush marks our niche.

## 13. Nakamura, Bishop, Man, Johnson, Manchester, Bajcsy — "How to Train Your Latent Control Barrier Function: Smooth Safety Filtering Under Hard-to-Model Constraints" (arXiv 2025)

Fetched: https://arxiv.org/html/2511.18606 (full text); https://arxiv.org/abs/2511.18606 (metadata)

Safety filtering for constraints that resist analytic modeling (a Franka must lift an open bag of Skittles without spilling): learn a CBF in the latent space of a world model (DINOv3 embeddings of wrist + third-person RGB, plus proprioception), trained from 735 trajectories including deliberate failures, with a margin classifier and an HJ-style safety critic; at runtime, sample actions around the nominal diffusion policy and keep those satisfying the latent CBF condition (thousands of samples in 10 ms on an A6000). The hardware numbers are the sharpest published quantification of the competence-vs-safety trade: unfiltered 62% failures / 38% success; a least-restrictive filter achieves 0% failures but converts every failure into a stall — success stays at 38%; their smooth CBF reaches 0% failures with 80% success. They admit the filter "can push the system into out-of-distribution states, reducing task performance" and that learned components preclude formal guarantees.

**Verdict: For the thesis in spirit, Against on cost.** It agrees the safety-relevant observation is *latent in signals the robot already logs* — but locates it in the camera stream and buys access with a world model, curated failure data, and a datacenter GPU; the least-restrictive row (failures become stalls, no successes added) is the published sibling of our finding that competence can live inside the unsafe region.

## 14. Beaudin, Krasowski, Nagpal, Seshia, Arcak, Mehr — "Any-Body Guard: Universal Safeguarding for Manipulation Policies via Action Masking" (X-Safe, arXiv 2026)

Fetched: https://arxiv.org/html/2606.22278 (full text); https://arxiv.org/abs/2606.22278 (metadata)

The closest competitor genre to our guard: a policy-agnostic, no-retraining runtime safeguard for manipulation policies (diffusion, VLA, teleop) that computes probabilistically safe polytopes in configuration space by sampling a collision oracle and ray-masks actions into them, requiring a URDF + forward kinematics, an object-based scene representation (from a separate perception module for image policies), and a MuJoCo-backed collision checker at 0.2–0.54 s per action. Scope is explicitly geometric: "safety constraints encompass self-collision and collision with quasi-static environment objects"; dynamic obstacles and "more diverse notions of safety, like not spilling liquid" are named as unsolved — grasp force and object crush are not in the hazard set at all. The trade is measured honestly: ~6% success degradation on Franka (vs 20% for the reachability baseline RAIL), 0.02% observed collisions against a 2% guarantee — and one instructive disaster: the Aloha VLA drops to 0% success under the guard because masking pushes it out of distribution. It dismisses candidate CBFs (no forward-invariance proof) and boundary projection (deployment instabilities).

**Verdict: Orthogonal on observability, head-on for positioning.** X-Safe claims the "universal manipulation safeguard" ground with perception + simulation oracles and no actuator telemetry, while declaring non-collision hazards out of scope — our guard is the complementary axis (contact/crush hazards, telemetry-only, no scene model), and their Aloha collapse is the extreme endpoint of the interference trade we quantified.

## 15. Cao, Li, You, Guo, Li — "PaCo-VLA: Passivity-Shielded Compliance Prior for Contact-Rich Vision-Language-Action Manipulation" (arXiv 2026)

Fetched: https://arxiv.org/html/2606.00515 (full text); https://arxiv.org/abs/2606.00515 (metadata)

A runtime shield for contact-rich VLA manipulation that shares our architectural stance: "rather than trusting VLAs with direct motor commands, PaCo-VLA treats network outputs as task-level compliance proposals" — the VLA proposes admittance schedules, and a passivity shield (box projection, passivity-margin enforcement, energy-tank bookkeeping) computes the only schedule actually executed, with stale predictions gated out on a 0.30 s timeout. No VLA retraining is needed, and the shield is controller-agnostic (random proposals and classical controllers pass through the same guard). The price of admission is hardware: a wrist-mounted six-axis force/torque sensor (KWR75B) and an admittance-controlled arm (AUBO-i5); results on connector insertion show 0/1000 passivity violations with the shield vs 505/1000 without, and 9/10 vs 6/10 real insertions against an energy-tank baseline. Motor current or servo-side telemetry is never used.

**Verdict: For the enforce-at-the-interface position, Against on the hardware floor.** It independently converges on "the learned policy proposes, a simple physical-invariant layer disposes," then buys its contact observability with exactly the F/T sensing and torque-controlled arm that low-cost fleets lack — the thesis in negative: where force sensors are absent, the shield's input must come from somewhere, and the actuator bus is what remains.

## Answers to the thread questions

**Q1 — Does any shield/filter operate from actuator bus telemetry alone (no dynamics model, no state-space constraint, no force sensor)?**
No. Nothing we read closes the loop from raw actuator telemetry to enforcement. The two nearest neighbors each supply half: (a) the proprioceptive collision-detection line (Haddadin et al.'s survey; Dalla Libera et al.'s GP residuals on motor currents) observes contact from actuation signals but either requires an identified rigid-body model with calibrated torque constants (momentum observer) or a per-robot learned current model — and in all cases stops at *detection*, never wrapping a policy, never enforcing a cap, and explicitly deferring thresholds and intended-vs-unintended discrimination; (b) the shield/filter line (Alshiekh, CBF, PSF, RAG, RTA, X-Safe, PACS, LatentCBF, PaCo-VLA) closes the enforcement loop but always from modeled state, scene perception, world models, or F/T sensing. Even the paper literally titled "model-free safety filters" (Yin et al.) consumes ground-truth state, a training simulator, and re-imports the model for certification. The specific combination in our guard — register history in, action clamp out, nothing learned, nothing modeled — is absent from this literature.

**Q2 — What do safety layers for learned manipulation currently require?**
As of 2025–2026, the published manipulation guards require, variously: robot kinematics/dynamics plus set-based reachability at 1 kHz and externally tracked human/object state with bounded error (PACS); a URDF, an object-based scene representation from a perception module, and a MuJoCo collision oracle at 0.2–0.54 s per action (X-Safe); a DINOv3-based world model, 735 trajectories including deliberately collected failures, an RL-trained safety critic, RGB cameras, and an A6000 (LatentCBF); or a wrist six-axis F/T sensor on an admittance-controlled industrial arm (PaCo-VLA). All assume robots far above the SO-101's price and sensing class; none runs on a bus-servo arm as shipped, and none addresses the gripper-crush hazard — X-Safe excludes non-collision hazards explicitly, PACS bounds pre-impact arm energy but not in-jaw grasp force.

**Q3 — Is "enforce at the actuator layer, don't learn safety" already argued?**
The "enforce, don't learn" half is old and canonical: Simplex (Sha 2001 — a simple reliable core guarantees critical functions so unverifiable complex software can be exploited) through RTA (Hobbs et al.: decouple safety enforcement from all other objectives; verification does not grow with primary-controller complexity and survives policy swaps) to shielding for RL (Alshiekh et al.). Our three-checkpoints-one-guard result is a textbook instance of their argument. The "at the actuator layer" half is not argued anywhere we found: RTA/shields monitor modeled state; RAG sits at the action interface but derives its safe set from a model; the collision-detection line reads actuator signals but never argues for it as the *enforcement* point for learned policies. The position "the actuator bus is the right shield interface because it is the only observation and actuation surface a fleet universally ships" appears to be unclaimed.

**Q4 — How do published shields handle the competence-vs-safety trade we measured?**
Three ways. (1) By theorem: minimal-interference / least-restrictive properties (Alshiekh §6, CBF-QP objective, PSF pass-through, Hsu Prop. 1) minimize *how often* the filter acts — but any success that requires violating the constraint is deleted by construction, and the literature almost never audits those deleted successes; our paired-episode accounting of successes-earned-by-over-gripping has no direct precedent we found. (2) By measurement: X-Safe reports a 6% success cost and one total collapse (Aloha VLA 0% under the guard, from distribution shift); PACS reports ~1 point; LatentCBF's least-restrictive baseline is the cleanest published analogue of our finding — it converts 62% failures into 62% stalls while adding zero successes, demonstrating competence that lives inside the unsafe region. (3) By design response: keep the filtered behavior in-distribution (PACS path-consistency, X-Safe ray masking vs projection), make filters smooth to avoid boundary chatter (LatentCBF, Hsu §6.1), train filter-aware policies (Hsu §7.4.3), or move safety into training with sensors and reward shaping (Huang et al., who also supply the canonical objection to hard caps: "many manipulation tasks require occasional, momentary, or variable high force").

## Summary — positioning and threats

**Positioning sentence.** Runtime shields for learned manipulation currently buy safety with exactly the resources low-cost fleets lack — dynamics models and reachability solvers (RTA/CBF/PSF, PACS), scene perception and collision oracles (X-Safe), wrist force-torque sensing on torque-controlled arms (PaCo-VLA), or world models trained on curated failure data (LatentCBF); we show that on a bus-servo arm the missing observation — contact — is already latent in the servo's own position-register history, and that a 30-line, model-free stall-plus-cap guard at the actuator interface, unchanged across three behaviour-cloned checkpoints, removes 96% of crush events at a competence cost we measure rather than assume. In the field's own vocabulary: a Simplex-style RTA whose monitor watches bus telemetry instead of modeled state, enforcing a hard constraint on a proxy variable no published filter family consumes.

**Most dangerous prior work.** Haddadin, De Luca & Albu-Schäffer (T-RO 2017) and the proprioceptive collision-detection line it canonizes. A reviewer can say: "current-based contact detection from actuation signals is 15-year-old practice, shipped in the iiwa and Franka — your stall detector is a threshold on a residual." The defense must be specific: (i) their reference methods need the identified rigid-body model (M̂, Ĉ, ĝ) and calibrated current-to-torque gains or joint torque sensors, none of which exist for a Feetech STS3215, and the model-light variants (current transients, GP residuals) still learn per-robot models and stop at detection; (ii) their hazard is link collision with humans, answered by stop/reflex — not grasp-force limitation protecting the manipulated object, which their own footnote flags ("potentially fragile objects") and never revisits; (iii) nothing in that line is evaluated as a shield around a learned policy with paired-episode competence accounting. Secondary threats: X-Safe owns the "universal manipulation safeguard, no retraining" framing (we must position as the complementary hazard axis — contact/crush vs geometric collision — and can cite their explicit exclusion of non-collision safety); PACS owns "safety filter for diffusion policies on a real arm" (we differ in hazard, hardware class, and sensing). LatentCBF's least-restrictive-baseline result should be cited *for* us: it independently shows filters exposing competence that lives in the unsafe region.

**Fleet-practice postscript.** The only guard the SO-10x fleet actually ships is LeRobot's `max_relative_target` — a clamp on the magnitude of the commanded relative position step, `int | None = None` (i.e., disabled) by default on the SO-100/101 follower, applied in `send_action` (fetched: https://github.com/huggingface/lerobot/issues/1483). It is command-side and contact-blind: it cannot distinguish free motion from a jaw stalled on a strawberry. The fleet ships the telemetry our guard consumes and, today, no runtime layer that reads it — which is the thesis, stated in the default config.
